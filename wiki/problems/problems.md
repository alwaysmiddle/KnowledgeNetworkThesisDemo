# Problems

Well-defined problems are the entry point to the pipeline. Everything else — ideas, decisions, specs — traces back to a problem.

A problem document answers:

- What is happening that should not be, or what is missing that should exist?
- Who experiences this and in what context?
- How do we know this is real? (observation, data, user feedback)
- What does good look like if this is solved?

Keep problem statements solution-neutral. Do not describe how to fix it here — that belongs in the ideas that follow.

Each problem links to the ideas generated for it and the decision that resolved it.
