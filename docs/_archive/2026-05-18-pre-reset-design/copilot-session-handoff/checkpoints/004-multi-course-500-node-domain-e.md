<technical_details>

**Core architectural decisions (cumulative across all sessions):**

1. **"Everything is a node"** — no nested data structures. Every entity is a first-class graph node.

2. **9 node types in 2 categories (NEW this session):**
   - **Knowledge (6):** Concept, Principle, Example, Assessment, Reference, Analogy
   - **Organizational (3):** Program, Course, Professor
   - Knowledge types subject to L1-L4 visibility filtering
   - Organizational types always visible (or separate toggle)
   - EVōC clustering naturally separates the two categories

3. **Assessment format field change (NEW, decided but NOT implemented):**
   - Old: `format: 'exam' | 'exercise' | 'quiz'`
   - New: `format: 'test' | 'exercise' | 'quiz'`
   - Quiz = mastery check for 1 concept
   - Test = mastery check for 2-3 concept cluster
   - Exercise = practice problem (unchanged)
   - NO midterm/final exams — all assessments are per-concept or small-cluster mastery checks

4. **Multi-course program (NEW this session):**
   - 6 courses: CS101 Python 101, CS201 Data Structures, CS301 Algorithms, CS302 OOP & Software Design, CS401 Databases, CS402 Operating Systems
   - 3 professors: Chen (CS101, CS301), Martinez (CS201, CS302), Lee (CS401, CS402)
   - ~500 knowledge nodes + 22 shared principles = 522 total
   - Course-level and concept-level cross-course prerequisites defined

5. **System edges (updated):**
   - `sys:contains`: Program→Course, Course→knowledge nodes, Concept→sub-concepts
   - `sys:teaches` (NEW): Professor→Course
   - Behavioral properties: `onDelete`, `exclusive`, `autoCreated`, `userEditable`

6. **`sys:contains` hierarchy:**
   - Program `sys:contains` all Courses + all Professors
   - Course `sys:contains` all its knowledge nodes
   - Concepts MAY `sys:contains` sub-concepts and tightly-bound Examples/Exercises
   - Principles are NOT contained by courses — shared across courses via `demonstrates` edges

7. **EVōC-primary architecture (from Session 4, documented this session):**
   - EVōC clustering = primary spatial layout (semantic grouping from embeddings)
   - Node-type L1-L4 = secondary visibility toggle (stable spatial layout)
   - Pipeline: nomic-embed-text-v1.5 (local) → EVōC (multi-granularity) → toponymy (cheap LLM)
   - Python FastAPI service on port 8001
   - C# backend calls Python service, caches with content hash
   - 3 WorldMap modes: Disjoint Hierarchical, Disjoint Flat, Overlapping Flat
   - ZMLT compound graph for detail view with semantic zoom

8. **Cross-course prerequisite map (key handoffs):**
   - CS101:List → CS201:Array, CS201:Linked List
   - CS101:Dictionary → CS201:Hash Table
   - CS101:Recursion → CS301:Divide and Conquer
   - CS101:Class → CS302:Inheritance
   - CS201:Binary Search Tree → CS401:B-Tree Index
   - CS201:Graph → CS301:Graph Algorithms
   - CS101:For Loop → CS402:Process Scheduling

9. **Node budget per topic:** 3-6 nodes per lecture topic (1 concept + 0-3 sub-concepts + 1 example + 1 exercise + 0-1 principle)

10. **All prior decisions still valid:**
    - 10 formal domain edges + 1 derived (`assesses`) + system edges
    - Colon-separated namespace convention (`sys:contains`, `sys:teaches`)
    - C# ASP.NET Core backend (ADR-001 locked)
    - Jena Fuseki in-memory for inference
    - Computed hierarchy (not stored)
    - Gap node: Class concept (no assessment applies to it)
    - Prerequisite chain: Variable → Conditional Statement → For Loop → Function → Class
