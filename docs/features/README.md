# Feature Specs

Feature specs are short contracts for the next implementation slice.

Use a feature spec when a behavior is close enough to build. Keep broad product
vision in `ROADMAP.md` and shared nouns in `SYSTEM_MODEL.md`.

Each feature spec should answer:

- What user behavior does this enable?
- What data model does it require?
- What UI states exist?
- What backend/API behavior is needed?
- What is out of scope?
- How do we verify it works?

Specs should stay small enough to revise after implementation.
